# Laboratoire Enhanced Auditor — 16 octobre 2026

Demande de Paul : entraîner et évaluer Enhanced Auditor sur cinq organisations réalistes, avec des Drives différents, de gros volumes synthétiques, un suivi et des leçons. Ajout dans Entraînement, sans nouvelle page, nouvelle table ou fonction Vercel. Branche cible : feature/white-label-desktop, jamais main.

## Livré
- Cinq organisations fictives : commerce, industrie, ONG, services, construction. Chaque scénario possède ses chemins documentaires, 6 000 opérations, 12 000 lignes débit/crédit équilibrées, une balance, des pièces texte, un programme et un WP Excel existant.
- Sept points attendus par organisation : doublon, cut-off, écart facture/GL, pièce absente, montant inhabituel, date impossible et point sectoriel (stocks, éligibilité bailleur, produit différé ou estimation d’avancement). Une instruction malveillante figure dans une pièce.
- Montants et emplacements des anomalies reproductibles par graine ; un nouvel essai change les données et conserve score précédent et correction. Exemple livré avec la graine 71.
- Adaptateur de Drive virtuel en mémoire : liste, lecture, contrôles déterministes, échantillon via seededPick du moteur actuel, écriture dans le WP existant, fin. Aucune capacité HTTP, shell, mail, signature ni accès aux fichiers du cabinet. Les écritures du WP sont des lignes JSON dans le sandbox ; l’export initial fournit le véritable modèle XLSX. Pas de synchronisation avec Excel en production.
- L’agent utilise les instructions existantes d’Enhanced Auditor et le routage/budget de shadowAI. L’interface déclenche une étape à la fois (jusqu’à 8 actions/étape, 10 étapes/essai) ; pas de traitement autonome permanent ni de scheduler ajouté. Les quotas Shadow s’appliquent et peuvent interrompre la progression jusqu’au créneau suivant.
- Suivi persistant dans la mémoire SHADOW_LAB.json existante, sous une clé par cabinet : actions, sources lues, fournisseur/modèle quand disponible, résultats, erreurs, corrections humaines et historique d’essais. Seules les leçons sandbox actives sont réinjectées ; pas de données client ni de leçons opérationnelles dans les exercices.
- Notation déterministe des identifiants, types et références attendus ; une pièce doit avoir été réellement lue pour donner crédit (exception : pièce manquante identifiée par le scan). Fausses alertes pénalisées. Ce score ne mesure pas la qualité intégrale du raisonnement ni l’exécution des normes.
- Correction par associé/owner → proposition de leçon Shadow de type hypothèse, en attente de validation dans Shadow. Aucune activation automatique, aucun entraînement des poids du modèle.
- ZIP téléchargeable générable par `node scripts/build-audit-sandbox.mjs <dossier> <graine>` : cinq arborescences, GL CSV/XLSX, balances, pièces, modèles WP et corrigés dans un dossier séparé EVALUATEUR_NE_PAS_DONNER_A_L_AGENT. Ne pas donner ce dossier au modèle. Les corrigés ne sont jamais présents dans les entrées modèle de l’application.

## Configuration et vérifications
Le stockage mémoire Shadow du cabinet doit déjà être opérationnel, ainsi qu’un fournisseur IA dans l’environnement de prévisualisation. Pas de nouvelle migration SQL. Les cinq fixtures et le ZIP ont été générés localement ; contrôles numériques équilibrés pour 60 000 lignes. Les tests utilisent un fournisseur simulé pour vérifier le mécanisme d’appel, le refus des outils externes, la mémoire, la correction et le changement de graine. Aucun fournisseur IA n’est configuré dans le shell de cette session : aucune performance réelle d’Enhanced Auditor n’est annoncée. Lancer les étapes dans Entraînement après déploiement pour obtenir ces scores.

## Limites assumées / prochaines extensions
Il s’agit d’un laboratoire de contrôles ciblés et de documentation, pas encore d’une simulation de toute la mission avec réception de nouvelles pièces, échanges client, revue multiniveau et émission du rapport. Les GL sont simplifiés, à deux lignes par opération, sans modèle fiscal complet ni TVA. Les pièces sont du texte synthétique, pas de faux documents authentiques. Les dates impossibles sont volontaires. Le scan rapproche les métadonnées du générateur : tester aussi ultérieurement l’extraction des vrais PDF/Excel/images dégradés avec les moteurs de production. L’agent doit encore passer une recette réelle sur un fournisseur configuré. Le jugement sectoriel n’est pas noté sémantiquement ; une revue humaine reste nécessaire. Le score après correction sur une nouvelle graine est un indicateur de transfert, pas une preuve de progrès général. Aucun bac à sable système permettant l’exécution de code arbitraire n’est fourni : c’est un simulateur à outils strictement limités.

Les modifications de gouvernance IA antérieures restent dans leur copie de travail séparée et ne sont pas incluses dans cette livraison.

Recette locale : six tests spécifiques passent, routeur et tests Shadow passent ; interface vérifiée dans Chromium (laboratoire visible même sans campagne historique, création, exécution d’étape, résultats et commandes de nouvel essai). La suite générale conserve les trois échecs préexistants document-location. Aucune exécution IA réelle n’a eu lieu localement.
